你知道那种感觉吗——打开自己的旧项目，既想拥抱它，又想把它埋得深深的？那就是我。旧的 `vai-rice.space` 很可爱，真的可爱。但它被各种拐杖、React 和 Tailwind 缠得太密，密到让人喘不过气：每改一处都要牵动三层别人的抽象，每加一套主题就是又一层「魔法」，说实话，我自己都不敢往里看。

于是在某个时刻，我做了对遗留代码最诚实的一件事：

> **全部删掉。重建。从零开始。**

不是重构。不是「渐进式迁移」。是彻底铲平，然后重写。

这是一个关于倔强开发者的故事：他迁到 Astro 7，扔掉 React，告别 Tailwind，和 `vadim-khristenko.github.io` 划清界限，重做 CI，用 Rust 写了三个小应用，教会网站自己收集统计数据——而且没有疯掉。嗯，几乎没有。剧透一下：整个过程里网络掉线掉得相当有规律，这个后面再说。

---

## 再见，React

没有私人恩怨。React 是很好的工具，我也不打算再写一篇「为什么框架是万恶之源」的宣言。但对于一个有一堆独特主题的内容站来说，它就像用显微镜钉钉子：又贵，又别扭，还心疼那台显微镜。

我不需要每个按钮上都跑一个运行时框架。我需要的是**孤岛（islands）**。

于是我走到了 **Astro + Vue**。Astro 输出静态 HTML——快、省、对 SEO 友好，浏览器在显示前不用「复活」任何东西。而沉重的交互，我只精准地挂在真正需要它的地方：

```astro
<MainPage client:only="vue" />
```

一个 `client:only`——整个 SPA 体验就活在浏览器里，其余一切保持干净、轻量的 HTML，在你眨完眼之前就加载好了。状态交给 **Pinia**：主题、模式、语言。三个 store，毫无仪式感。

React 走了。世界安静又舒服。`package.json` 里出现了一个洞——而它很美。

## 你也一样，Tailwind

这一段几乎算是心理治疗。

我诚实地、敞开心扉地检查过：**Tailwind 在项目里根本没被用到。** 没有一个 `md:flex`，没有一个 `@apply`，没有一串那种把标记变成冷战密码的类名花环。它只是躺在依赖里，拖着自己的配置、自己的构建步骤、自己的 PostCSS——却什么都不做。典型的项目寄生虫：「以防万一」搬进来，然后就住下了。

因为所有样式早就快乐地活在自定义 CSS 变量上：

```css
.card {
  background: var(--bg-card);
  border: 1px solid var(--border);
  border-radius: var(--radius-lg);
  font-family: var(--font-body);
}
```

每套主题只是覆盖这些 token——`--bg`、`--primary`、`--radius`、`--font-display`、`--shadow`、`--motion`——组件读取它们，不多问一句。这就是全部的「设计系统」：一组变量，加上一份尊重它们的约定。

于是 `@astrojs/tailwind` 和 `tailwindcss` 本体一起走向了夕阳。少一个依赖，少一整层魔法，少一个我反正从没看过的配置——而**零损失**。零。没有一个像素受伤。

如果你的项目里有一个依赖，你没法在十秒内当众解释清楚——那它不是依赖，是房客。

## Astro 4 → 7：跨越三个大版本

这里就好玩了。好玩的意思，是凌晨三点修水龙头那种好玩。

项目停在 **Astro 4**。外面已经是 **Astro 7.0.7**。中间隔着：全新的 content layer、改了名字的 API，还有几个 changelog 只用一行带过、实际却是在空房间里骂半小时的惊喜。

大改动：

- `src/content/config.ts` 搬到了 **`src/content.config.ts`**——对，就这样，少一个文件夹，网上一半的教程瞬间过时；
- 集合现在需要一个 **loader**：

```ts
const blog = defineCollection({
  loader: glob({ pattern: '**/*.md', base: './src/content/blog' }),
  schema: z.object({
    title: z.string(),
    description: z.string(),
    pubDate: z.coerce.date(),
    tags: z.array(z.string()).default([]),
    lang: z.enum(['ru', 'en', 'zh']),
    translationKey: z.string(),
  }),
});
```

- `post.slug` 悄悄变成了 `post.id`。API 里一个字母的差别——换来半小时在模板里追 `undefined`。

改上几处，重新构建——然后是那句神圣的 `✓ 6 page(s) built`。顺手还升级了 **Vue 3.5**、**Pinia 3**、**Vite 8** 和 **TypeScript 7**。活在刀尖上：真要坏，也会坏得漂亮，而且第一个坏。

## 八套主题，八种心情

网站会换装。而且这不是「换个强调色、加个深色背景」。这是八种**不同的体验**，每一种都有自己的排版、自己的动效、在读者脑海里响起的自己那套界面音效。

这一版我不只是把主题搬过来——我从零重画了它们，因为旧的只是「还行」，而我想让它们「对」。

- **Modern**——瑞士式编排：钴蓝与朱红，大号排版，大量留白，一张即使看不见也能感觉到的网格。给来读东西的人。
- **Windows 95**——像素级的怀旧。窗口式的分区，带真正的标题栏和关闭按钮（真的，别按），厚重的立体边框，系统字体，还有——没错——给特别好奇的人准备的蓝屏彩蛋。
- **Mac Classic**——铂金灰，条纹标题栏，来自另一个年代的圆角矩形。安静、礼貌、略带一点居高临下。
- **Windows 11**——亚克力质感、柔和阴影、圆角、干净的动画。现代，又有点无菌，像一条被好设计师收拾过的医院走廊。
- **macOS 26**——玻璃、纵深、图层。大量透明，以及对间距的尊重。
- **Snackers**——最放肆的一个。颜色、动感、个性。一套明显不打算严肃的主题，而这正是它最好的特质。
- **Classic**——朴素、平和、「就是个网站」。给想要内容而不要马戏的人。
- **Terminal**——等宽字体、光标、黑底绿字、毫无怜悯。我的老家。

每套主题就是一组 token 加几个专属组件。样式绝不复制粘贴：引擎只有一个，戏服有八套。

## 自己的域名：再见，`vadim-khristenko.github.io`

很长一段时间，网站住在 `vadim-khristenko.github.io`。能用吗？能用。但那就像拿着 mail.ru 邮箱去面试：功能上没问题，可总留下点什么。又长、又臃肿、又是借来的。

现在有了 **`vai-rice.space`** 和 **`www.vai-rice.space`**。自己的域名，自己的规矩。

听起来像个十五分钟的任务。实际上——是一整晚和 DNS 跳舞，因为 DNS 永远、**永远**是那个「本不该坏的东西偏偏坏掉」的地方。

需要理清的东西：

- **顶级（apex）域名**——四条指向 GitHub Pages IP 的 `A` 记录（以及给 IPv6 的 `AAAA`，因为我们不是野蛮人）。
- **`www`**——一条单独指向 `vadim-khristenko.github.io` 的 `CNAME` 记录。不是 apex。永远不是 apex。
- **构建根目录里的 `CNAME` 文件**——否则 GitHub Pages 每次部署都会开心地忘记自己是谁、为了什么。
- **HTTPS**——Let's Encrypt 证书会自动签发，但要等 DNS 完全生效之后。也就是说：你配好了，一切正确，然后你就坐着等。刷新。再等。
- **重定向**——好让 `www` 和 apex 在搜索引擎眼里不是两个不同的站点，而是规范化成同一个实体。

单独一个流派，叫**生效期间调试**。`dig`、`nslookup`、三个不同的 DNS 解析器、浏览器缓存、系统缓存、运营商缓存，以及笼罩这一切之上的那种挥之不去的感觉：互联网在专门针对你。

剧透：互联网真的在针对我。这个，往下两节再说。

## GitHub Actions：从头重搭的流水线

旧的部署……嗯，它是存在的。一个 workflow 在那儿做点什么，要是它挂了，我通常就重跑一遍，然后祈祷好运。那不是 CI，那是一种仪式。

全部重搭：

- **构建**——装依赖、Astro 构建、类型检查。类型不过——整条流水线失败，没有「诶回头再修」。
- **缓存**——依赖和 Astro 产物在多次运行之间缓存。三分钟的构建变成了不到一分钟。
- **WASM 构建**——单独一步，带自己的 `cargo` 缓存。Rust 编译慢是生活的事实，但每打个喷嚏就重新编译一遍，那已经是自虐了。
- **部署**——通过官方的 `actions/deploy-pages`，配上正经的 `environment`，而不是靠意念手写地往 `gh-pages` 推。
- **一个 cron 任务**负责统计——这个马上就讲。

现在推一次 `main` 不再是「碰碰运气」，而是「它现在就会构建好，而且我知道为什么」。

## 无痛的实时统计

以前，每个页面都会**为每一位访客**去请求 GitHub API。这个想法听起来不错，直到我想起了速率限制。未认证 IP 每小时六十次请求。来一个好奇的人，点开五个标签页——其他所有人的统计就变成南瓜了。

解决办法简单得令人尴尬：**让数据提前收集好。**

我写了一个自主脚本，通过 cron **每六小时**在 GitHub Actions 里跑一次。它去请求 API，收集星标、fork、语言分布、最新发布——然后把这一切放进公开的 `/data/stats.json`。网站只需读取现成的 JSON。访客零请求、零限制、零焦虑。

一个我没计划、却非常满意的附赠：如果 GitHub API 突然挂了——网站根本察觉不到。它已经有数据了。是最近一次的数据，但终归是数据。降级而非宕机，大概是我最喜欢的工程情绪。

## 重新想过的博客

旧博客是一个「有帖子的页面」。技术上是博客。感受上是垃圾场。

把整个概念重做了：

- **多语言是一等公民。** 每篇帖子都有 `translationKey`，切换语言带你去的不是首页，而是**同一篇帖子的另一种语言版本**。俄、英、中。一路上什么都不丢。
- **界面翻译按区块拆成微文件。** 不是一个一千五百行、令人发指的 `translations.json`，而是整齐的小块：导航归导航，页脚归页脚，博客归博客。编辑是享受，找某一行只要一秒。
- **一份 Zod schema。** 在 frontmatter 里漏了字段？构建直接失败。不是「一周后在生产环境某处失败」，而是就在这里，带一条清晰的报错。
- **成年人的 SEO：** 带横幅的 Open Graph、`JSON-LD` 标记、sitemap、robots。不是因为我在追流量，而是因为做一半比不做更糟。
- **真正的品牌图标**（`simple-icons`）取代千篇一律的小圆圈。小事一桩。但正是这些小事，累加出「这个站是有人亲手做的，而不是一晚上套模板拼出来的」那种感觉。

## 写给 AI 的资料：`/llms.txt` 与 `/for-ai/`

我们坦诚点：在你网站上走动的不只有人类。爬虫、助手、智能体也在走，而且只会越来越多。大多数网站迎接它们的方式，和 2010 年迎接 Googlebot 一模一样：一堆 div，外加一份美好的祝愿。

我决定换个方向，做了一份**明确写给 AI 智能体的资料**：

- **`/llms.txt`**——一份机器可读的摘要：我是谁、有哪些项目、东西都放在哪、什么可以引用。没有营销噪音，没有「创新解决方案」，只有结构化的事实。
- **`/for-ai/`**——一个人类可读（也智能体可读）的页面，提供扩展上下文：技术栈、原则、项目、链接、许可。

想法很简单：既然模型反正都会谈起我——那就让它谈得**正确**，而不是靠三年前缓存的碎片去幻觉。给智能体一个像样的来源——换回一个像样的关于你的形象。这不是未来主义，只是对一种新读者的礼貌。

## 对了，网络一直在掉线

单独的一章，少了它这个故事就不诚实。

这次迁移的很大一部分，是在我称之为「网络按时供应，但时间表未知」的条件下完成的。网络掉线。不是「加载很慢」——而是干脆**断掉**，断在 `npm ci` 中途，断在 `cargo build` 中途，断在一次推送中途，断在 DNS 生效中途——而那个你已经连续检查了三个小时的 DNS，你都分不清到底是你这边解析不了，还是全世界都解析不了。

这当然是一种独立流派的地狱。你不知道是自己配置里有错，还是某个包只是没送到。你去修那些没坏的东西，因为真正的故障在外面，而你看不见它。调试变成了算命。

但它对脑子大有好处。当网络不再是理所当然，而是一种特权，你会突然开始珍惜：

- **本地缓存**（从缓存跑 `npm ci` 就是爱）；
- **最小依赖**（每多一个包，就多一次「构建没送到」的机会）；
- 对开发整体的 **离线优先** 态度；
- 以及 **会降级而不是宕机的系统**——正是为了这套哲学，我一开始才去搭那个统计缓存。

讽刺的是，不稳定的网络反而让网站变得更好。不是因为本该如此，而是因为——疼痛是位出色的建筑师。

旧网站是一份不错的草稿。它诚实地完成了自己的使命，教会了我它该教的，然后体面地退场。

新的这个，是我从一开始就设想的样子——只是那时我还没有胆量承认：重写比修补更容易。

没有 React。没有 Tailwind。有自己的域名。有八套主题、三个 Rust 小应用、自主统计、诚实的 CI，以及一份写给那些将在你之后来读这篇文章的机器的资料。
