几乎每位 VTuber 都有一个粉丝维基，而它们几乎都在 FANDOM 上。文章上面盖着广告，一个页面要加载好几秒，皮肤改不了，社区写下的一切都放在别人的平台上。我是 Filian 社区的一员，我们被称为 Snackers。某一天我想：我们应该有一个属于自己的地方，快、好看，而且是我们的。

于是有了 **NotAnotherWiki Engine**，代号 NotAnOtherVTUBERwiki。第一个跑在它上面的维基是 **FilianWIKI**，现在在 [beta.filian.wiki](https://beta.filian.wiki) 公开测试。

先说重要的一点：这是一个**粉丝项目**。我们不是 Filian，不代表她发言，也不属于任何 ARG。维基的每一页底部都写着这句话，这不是走形式：当一位主播正在进行一场替代现实游戏时，任何带着她名字的网站都很容易被当成线索。这里没有线索。

## 最后做出了什么

我在 8 月 31 日从一个空仓库开始。七周后，仓库里有 264 次提交、八个 Rust crate、大约 5.6 万行代码和将近 600 个测试。0.6.1 版本今天发布。

![FilianWIKI 上的「Filian」条目：信息框、脚注，以及英文原文已更新的提示](/blog/notanotherwiki/article.webp)

引擎现在能做的事：

- 用 **Markdown** 写条目，支持脚注、目录、信息框、标签页、导航框和时间线；
- **模板和模块**：模板嵌入页面，模块直接在服务器上计算页面的一部分；
- 一个维基里有**多种语言**，每篇条目都有自己的译本；
- 逐词对比的编辑历史、每个页面的讨论区、监视列表和通知；
- 角色和管理员、页面保护、待审编辑队列和回退；
- 举报、审计日志、按地址封禁、针对新账号的防垃圾规则；
- 通过 Discord 和 Telegram 登录，上传图片、音频和视频；
- 从 MediaWiki 和 FANDOM 导入，连同编辑历史；
- 位于 `/api/v1` 的公开只读 API。

## 为什么不用 MediaWiki

MediaWiki 很适合维基百科，但它带着 PHP、一门没人记得住的标记语言，以及改起来很痛苦的皮肤。我想要的是另一种东西：

- **Markdown 优先。** 大家每天都在 Discord 和 Telegram 里写它，不用学。
- **皮肤就是一个模板文件夹。** 模板用 MiniJinja，主题就是一个颜色文件。FilianWIKI 用的 Snackers 皮肤，只是默认皮肤之上的一个文件。
- **在树莓派上也很快。** 服务器用 Rust 和 axum，页面以渲染好的形式缓存，响应带 ETag 并支持条件 GET。
- **关掉 JavaScript 也能读。** 条目、搜索和历史在关闭 JS 时都能用。连登录也不需要脚本：在另一台设备上确认就行。
- **AGPL-3.0**，这样谁也不能拿走这个引擎去做成闭源产品。

技术栈：Rust、axum 和 sqlx，PostgreSQL 18，Valkey 9。旁边还有一个 Bun 写的 worker，负责绘制 Mermaid 和 Graphviz 图表，并为手机生成图片的 WebP 副本。filian.wiki 的落地页用 Vue 写成，为每种语言预渲染。

## 懂维基的 Markdown

纯 Markdown 对维基来说不够用，所以我扩展了它。脚注按引用顺序汇总到页面底部。信息框直接以块的形式写在正文里。模板支持 `#switch` 和 `PAGELANGUAGE`，所以同一张 VTuber 卡片会以它所在页面的语言显示。VOD 表格有一个 `:::timeline` 块，读起来就像直播录像的章节列表。7TV 表情写作 `:name:`，并保存在维基本身，不依赖别人的 CDN。

图表又是另一个故事。Mermaid 输出 SVG，而 SVG 本质上就是带着自己脚本的 HTML。所以 worker 按照允许的标签和属性清单重新生成 SVG，清单之外的东西根本到不了页面上。

从 FANDOM 导入也有惊喜。`Special:Export` 页面藏在 Cloudflare 的验证后面，我没有去绕过它。但 `api.php` 不经任何验证就返回同样的 XML。导入器解析维基文本，把 tabber 变成标签页，并把编辑历史一起搬过来。

## 一篇条目，多种语言

FilianWIKI 从第一天起就是双语的。每篇条目都有语言，译本链接到原文。如果原文在翻译之后有改动，条目上方会出现「原文已更新」的提示，并附上差异链接，就像上面的截图那样。不带语言的地址会打开读者所用语言的版本。

语言也带来了最新的一个 bug。今天发现，「最近更改」页面上，译本的差异和历史链接在生成时没有带语言前缀。俄语条目的历史链接会指向英语条目，而英语条目不存在时就是 404。修复只用了一个方法：链接现在按照所显示那次编辑的语言生成，而不是按页面打开时的语言。当天 0.6.1 就上了测试版。

## 没有 AI 流水线味的皮肤

特殊页面的第一版看起来就像现在一半的互联网：卡片、渐变、圆点、发光。某一刻我老实承认这就是 AI 流水线产物，然后重做了。

搜索现在看起来像一份**语词索引**：命中的词位于行的正中间，左右两侧是它的上下文。一眼就能看出是条目的哪一节命中了，以及为什么命中。

![搜索「minecraft」：命中项居中对齐，就像语词索引](/blog/notanotherwiki/search.webp)

特殊页面变成了一本**参考手册**，「最近更改」变成了一条时间线，带有时间、每次编辑的大小，以及一根显示编辑幅度的条。

## 我记得的那些 bug

这类项目最有意思的部分不是功能，而是出过的故障。

**一个空查询要四秒。** 连接 Postgres 的测试有时会在第一次连接时卡上好几秒。罪魁祸首是 `localhost`：在 Windows 上它先解析成 IPv6 `::1`，而 Docker 监听的是 IPv4，于是每个新连接都要先等一次拒绝。现在到处都用 `127.0.0.1`，这正好是项目的第八次提交。

**「已应用」的迁移。** sqlx 在编译时把迁移嵌入二进制文件，而 cargo 不把迁移文件夹当作构建输入。新增一个迁移，运行 `migrate`，日志写着「applied」，实际上什么都没应用：二进制是在文件出现之前编译的。在 alpha 上，这让登录返回了两分钟的 500。修复只需要 `build.rs` 里的一行（对迁移文件夹设置 `rerun-if-changed`），而每次部署后我都去看 `_sqlx_migrations` 表，而不是看日志。

**所有页面十二分钟的 500。** 对零行做 `bool_or` 聚合，返回的是 `NULL` 而不是 `false`。我在 sqlx 里把这个字段标成了必填，查询照样编译通过。问题是它在每次浏览页面时都会执行，而几乎没有哪个页面有待审编辑。在热修复上线之前，alpha 在所有页面上都返回 500。现在这类聚合都包在 `COALESCE` 里，热路径上的每个查询都有针对空结果的测试。

**记着旧东西的缓存。** 渲染好的页面按文本哈希缓存。如果渲染器变了而文本没变，哈希就不会变，维基会继续返回旧的 HTML。所以缓存键里包含渲染器版本号，而且必须在修改 Markdown 输出的同一次提交里提升它。有一次我忘了，alpha 一直显示旧的标记，直到我搞明白原因。

**落地页上的黑屏。** 在 Vue 的 scoped CSS 里，选择器 `:global(.has-3d) .fallback` 会被编译成单单一个 `.has-3d`。这个类挂在 `<html>` 上，所以页面加载一秒后整个落地页就变透明了。看起来像 WebGL 的 bug，结果只是一行 CSS。

**偷走机器人的本地副本。** Telegram 规定每个机器人只能有一个更新接收者。我用生产配置在本地跑了维基，本地副本就开始从测试版那里抢消息。现在本地运行总是关闭机器人轮询。

**用完的磁盘。** 这样一个 workspace 的 `target/` 文件夹很容易涨到 80 GB，而空间用完时 rustc 不会给出任何有用的提示，直接崩溃。现在我像盯测试一样盯着它。

## 安全，因为这里是人人都能写的地方

维基是任何人都能写任何东西的地方，所以我把所有输入都当作敌意输入：

- 每个页面都带有 Content Security Policy 和一次性的脚本 nonce；
- 来自其他网站、会改变状态的请求一律拒绝；
- 数据库里只存会话的摘要，cookie 带 `__Host-` 前缀；
- 搜索片段按文本转义，而不是当作 HTML 解析；
- Markdown 渲染的耗时与文本长度呈线性关系，差异计算的成本也有上限，一次巨大的编辑拖不垮服务器；
- 保存页面使用 compare-and-swap：两个人同时编辑时，第二个人会收到 409，而不是悄悄覆盖第一个人的文字；
- 开销大的路由按地址限流，按地址封禁只禁止写入，不禁止阅读；
- 跟踪日志会抹掉 URL 中的令牌和 OAuth 代码，开发用登录拒绝在公网地址上启动。

依赖我也会盯着：最近几天 ammonia 因为新的安全公告更新了两次，最新一次是 RUSTSEC-2026-0373。

## 管理与人

维基最难的部分不是代码，而是人。所以很多时间花在了维持秩序的工具上：角色和管理员、页面保护等级、带回退的待审编辑队列、能看到管理员回复的举报、可读的审计日志。不适合所有年龄的页面会先显示警告，读者同意之前页面不会打开。

备份每天进行，每周我会检查一次它们是否真的能恢复。从来没人恢复过的备份，只是一种希望。

## 项目现在在哪里

从 10 月 6 日起，FilianWIKI 进入公开测试：任何人都可以用 Discord 或 Telegram 登录并开始编辑。关于直播、年表、术语表以及 Filian 身边的人的条目都附有来源，每个事实都能通过脚注核对。
